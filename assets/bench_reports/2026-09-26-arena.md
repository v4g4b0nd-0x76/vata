# Arena benchmark record — 2026-09-26

## Scope and comparability

This report records measurements supplied from the Linux profiling host while
working on the packed write-cursor change. The host exposes 4.6 GHz performance
cores and 3.3 GHz efficiency cores. It is **not** an Apple M4 Pro result.

`make profile-perf` and `make profile-c2c` run the three Criterion benchmarks in
`arena_bench` for a fixed profiling duration. A faster version can execute more
iterations, so absolute instructions, cycles, and sample counts are not
per-operation comparisons. IPC, miss rates, and normalized C2C events are the
useful directional signals.

`make workload` is a separate, fixed workload: 2,000,000 records of 1 KiB, four
local readers, with medians reported per 100,000-record batch. One batch appends
102.4 MB and the four readers each copy the same 102.4 MB, for roughly 512 MB of
aggregate local memory movement. Its roughly 10 ms result is memory/cache work;
it is not NIC throughput.

## Changes represented

The comparison below is before and after replacing the two shared cursor atomics
(`slab_idx` and `offset`) with one cache-line-aligned packed `AtomicU64`. A reader
now performs one acquire load rather than two; the writer publishes one packed
release value. The arena's public API and record-copy semantics did not change.

different delivery model, not a safe atomic-layout tweak.

## Fixed 100k-batch workload

### Current unpinned baseline, after packed cursor

Six recorded write medians (ms):

```text
10.178, 10.093, 10.534, 9.447, 9.837, 9.732
```

Median: **9.965 ms**. The read median across all consumers tracks the writer
closely. Steady-state allocations: **0 calls, 0 bytes**.

### Linux P-core affinity experiment — rejected and not retained

The writer and four readers were pinned to separate 4.6 GHz performance cores.
Five write medians (ms):

```text
9.847, 10.529, 10.476, 9.687, 10.083
```

Median: **10.083 ms**. This is within noise and slightly slower than the unpinned
baseline, so the affinity implementation and its `libc` dependency were removed.
No production or benchmark affinity code remains.

## Interpretation and next measurement

The approximately 10 ms batch time is already dominated by copying the record
payload to four local consumers. It corresponds to about 10.2 GB/s for the writer
alone and about 51.2 GB/s of aggregate counted local memory movement when the
four reader copies are included. This is not a network claim.

For remote consumers, end-to-end throughput is bounded by the NIC/link and its
packet, kernel, DMA, and backpressure costs. The next relevant performance test is
an end-to-end sender/receiver benchmark on the target NIC, rather than adding a
more complex arena delivery design.

Run the fixed workload from the same revision, then append the complete output to
this section. macOS does not provide the Linux `perf c2c` or THP measurements, so
compare the workload median and allocation count only.

```sh
cd ~/projects/personal/vata

```

Record the commit, macOS version, CPU counts, and complete `make workload` output.
